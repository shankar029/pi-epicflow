# Research brief — Vendor-neutral file-based agent memory (BL-003)

**Question:** Current (2025–2026) best practice for persisting agent/LLM session memory across runs in a file-based, vendor-neutral way — (a) Claude's memory tool, (b) `claude-mem`, (c) canonical field objections.
**Session goal:** Compare pi-epicflow v0.13's `.pi/project/` brain against the two named systems; produce an actionable steal/diverge list.
**Brain primed:** yes (`index.md`, C-001..C-004, `decisions.md` shape, BL-003, `skills/project-memory/SKILL.md`).
**Budget used:** 0 `web_search` (pi-web-access not installed — see §7); 2 `curl` fetches against the two URLs the steward supplied.
**Partial:** true — claude-mem's deeper docs live on `docs.claude-mem.ai` and were not fetched; synthesized from README only.

## 1. Claude memory tool — design fingerprint

- **Storage shape:** a **file tree** under `/memories`, mediated by a fixed tool schema (`view`, `create`, `str_replace`, `insert`, `delete`, `rename`). Files are free-form text/Markdown/XML; *the model* decides the layout. [1]
- **Write semantics:** **client-side execution.** The model emits tool-use; the harness performs filesystem ops. Anthropic stores nothing (ZDR-eligible). The model is told to write *during* work — "ASSUME INTERRUPTION: your context window might be reset at any moment." [1]
- **Retrieval model:** **eager prelude.** The system prompt mandates `view /memories` before any other action every session, then selective `view` of individual files. No semantic search — `ls` + `cat`. [1]
- **Key constraints:** `str_replace` requires unique match (errors on duplicates); 999,999-line cap; path-traversal must be enforced by the harness; size + age pruning recommended. Pairs with server-side **compaction** and client-side **context editing**. [1]
- **Multi-session software pattern (explicit recommendation):** an **initializer session** that bootstraps a **progress log** + **feature checklist** + **startup-script reference**; later sessions read those first, update progress before close. "Work one feature at a time; mark complete only after end-to-end verification." [1]

## 2. claude-mem — design fingerprint

- **Storage shape:** **SQLite** (`sessions`, `observations`, `summaries` + FTS5) **plus Chroma** vector DB for hybrid keyword+semantic search. Not file-tree, not plain-text. [2]
- **Write semantics:** **automatic, lifecycle-hook-driven.** Five Claude-Code hooks (`SessionStart`, `UserPromptSubmit`, `PostToolUse`, `Stop`, `SessionEnd`) capture tool-use observations passively; an AI step generates **semantic summaries** asynchronously. No trigger phrases; no model-directed writes. [2]
- **Retrieval model:** **lazy / progressive disclosure.** Three-layer MCP workflow: `search` (compact index, ~50–100 tok/result) → `timeline` (chronological neighbors) → `get_observations` (full bodies, ~500–1k tok) only for filtered IDs. Claimed ~10× token savings. Observations have stable integer IDs and citable URLs. [2]
- **Constraints:** Node ≥18, Bun, `uv`, SQLite; persistent worker on :37777; `<private>` tags for privacy; Apache-2.0; v6.5.0; adapters for Gemini CLI / OpenCode but vendor-shape is Claude-Code. [2]

## 3. Where pi-epicflow already aligns

- **Append-only structured artifacts** (C-002, SKILL Hard rules) ↔ memory-tool's `create`/`str_replace`/`insert`. Both treat memory as durable text. Pi forbids editing history except a narrow `in-progress` placeholder window in `sessions.md`, matching Anthropic's trustworthy-progress-log principle. [1]
- **Initializer + per-session progress log** (SKILL "Session lifecycle": open `in-progress`, close as `achieved`/`paused`/`abandoned` with DEC/BL ids) is Anthropic's multi-session software pattern with stricter terminology. [1]
- **Read-on-entry discipline** (`index.md` mandatory load) ↔ Anthropic's `view /memories` prelude. [1]
- **Verify-before-complete** (C-001 anti-stub + epic gates) ↔ Anthropic's "only mark complete after end-to-end verification." [1]
- **Stable citable IDs** (DEC/BL/L/C-NNN) ↔ claude-mem's observation IDs. [2]

## 4. Where pi-epicflow deliberately diverges

- **Schema-first, not free-form.** Six fixed Markdown files with templated entries vs. "model decides the layout." Less flexibility; far less drift; humans can grep DEC-NNN deterministically.
- **Trigger-phrase writes, not always-on hooks.** SKILL "Trigger detection" fires on user utterances (`"let's go with X over Y"` → DEC; `"defer X to v2"` → BL). claude-mem captures everything via hooks then summarizes. Pi gets curated low-volume signal; claude-mem gets exhaustive recall with retrieval cost.
- **Plain Markdown, no DB / worker / summarizer LLM.** Any pi/Claude/Gemini/Codex session that reads files participates; `git diff` is the review tool. claude-mem requires Bun + SQLite + Chroma + uv + :37777.
- **Steward + personas, not lifecycle hooks.** Writes flow through the main agent + `epicflow-*` sub-agents with bounded budgets and refuse templates. Cost: writes can be missed if the model forgets; mitigated by the end-of-task sweep.
- **No retrieval layer.** `index.md` routing + grep only. Acceptable at small N; a known cliff (see §7).

## 5. Steal-list (ranked ROI ÷ effort)

1. **Adopt "ASSUME INTERRUPTION" framing in SKILL.md.** One paragraph reinforcing *write during work, not only at end-of-task sweep*. Zero code. High ROI for write completeness on long/crashy sessions. [1]
2. **Tighten the read-on-entry rule.** SKILL says read `index.md`; tighten to "before any non-trivial action, restate the DEC/BL/C/L ids you're working under." Reduces stale-context drift, the canonical field failure mode. [1]
3. **Progressive-disclosure for `index.md`.** Add per-section anchors and a "what to read for X" routing table so steward (or a future retriever) can pull the *page* it needs without slurping every artifact. Mirrors claude-mem's 3-layer idea without a DB. [2]
4. **Size + age caps with explicit rollover.** Anthropic recommends pruning. Document soft caps per artifact (e.g. `decisions.md` > ~500 entries → split into `decisions-archive-YYYY.md` referenced from `index.md`). Append-only preserved; load cost bounded. [1]
5. **Uniqueness invariant for the one mutable line.** The `in-progress` placeholder edit in `sessions.md` is the sole non-append op; mandate that its line be byte-unique so any future `str_replace`-style tooling is safe. [1]

## 6. Reject-list

1. **Reject the claude-mem stack (SQLite + Chroma + Bun worker + auto-summarizer).** Breaks vendor-neutrality and the "plain Markdown the user can `git diff`" charter; binary state defeats review; gains don't kick in until artifact volume is large, which pi-epicflow is nowhere near. [2]
2. **Reject AI-generated session summaries.** They are the canonical source of stale-context drift in this design space — summaries smooth over the exact "we chose X over Y because Z" nuance that DEC entries capture verbatim. Keep human/steward-authored summaries. [2]
3. **Reject hook-driven capture-everything.** PostToolUse capture is the noisy-log antipattern. Pi's trigger-phrase model is intentionally lossy; that's a signal-to-noise feature. [2]

## 7. Open design question for the maintainer

**When `.pi/project/` outgrows grep, what's the retrieval story?** Today `index.md` + grep + persona priming handles ~tens of entries. At hundreds (likely by v0.16–v0.17, especially if BL-004's global brain lands), the steward will start missing relevant prior DECs. Three options:

- (a) Stay grep-only; enforce size caps + archive rollover (cheap, may starve recall).
- (b) Ship an optional `epicflow-retriever` persona doing keyword+heuristic search over the brain (Markdown-only, no index build).
- (c) Optional sidecar FTS5 index built on `/project-review` (still file-based, reproducible from Markdown).

Recommend **(b) now, defer (c) to v0.15+ if (b) saturates** — preserves "plain Markdown is canonical." Needs a DEC.
