# v0.13.0 — Project memory

> **Pi sessions stop forgetting across runs.** A second pillar joins the
> epic workflow: a persistent, file-based project brain at
> `.pi/project/` that pi reads on entry and writes to autonomously on
> trigger phrases. Append-only, with a hard anti-stub rule and five
> custom `epicflow-*` sub-agent personas.

## TL;DR

- **New skill:** `project-memory` — auto-loaded in any repo with
  `.pi/project/`. Handles reads, trigger-driven writes, end-of-task
  sweeps, and goal-tracking transparently.
- **6 brain artifacts:** `charter.md`, `conventions.md`, `decisions.md`,
  `backlog.md`, `sessions.md`, `index.md` (under `.pi/project/`).
- **5 custom personas:** `epicflow-{scout,researcher,worker,reviewer,oracle}`
  — replace generic pi-subagents with mandatory `.pi/project/` primes,
  bounded budgets, and strict output contracts.
- **4 slash commands (mostly optional):** `/project-init`,
  `/project-onboard`, `/project-review`, `/session-end`. Day-to-day you
  invoke none of these — the skill handles writes autonomously.
- **Hard anti-stub rule (C-001):** no `TODO` / `FIXME` /
  `NotImplementedError` / bare-`pass` bodies in shipped code, ever.
  Enforced by the reviewer's grep gate.
- **Bug fix from dogfood:** the first brain audit on this repo caught a
  real pre-existing C-003 violation — `pi-epic-status` is missing its
  PowerShell mirror (logged as BL-007).

## Why this exists

The epic-workflow pillar solves multi-feature ship-quality. It does not
solve the everyday pi pain that lives one layer down:

- Decisions made on Tuesday evaporate by Wednesday.
- Out-of-scope items get forgotten the moment the session ends.
- Pi re-asks the same question across sessions.
- Pi ships `TODO: implement later` stubs that look done but aren't.
- Pi drifts from "fix the auth bug" into a user-model refactor nobody
  asked for.

Project memory addresses all five with a file-based, append-only brain
and a few automatic discipline rules.

## The five mechanics

1. **Stated session goal.** Pi asks for (or proposes) the goal on the
   first non-trivial turn. The goal becomes a guardrail — off-goal turns
   prompt "park or pivot?".
2. **Trigger-driven writes.** Pi watches for "defer", "decided", "always
   do X", "out of scope" and writes the entry the moment the phrase
   fires — not at session end. Survives crashed sessions.
3. **End-of-task sweep.** Before any "done" report, pi re-scans for
   missed triggers and diffs code-changed vs brain-recorded.
4. **Append-only with supersedes.** Nothing is edited or deleted.
   Reversals are new entries pointing to what they replace. (One narrow
   exception: in-progress placeholders in an open `sessions.md` entry
   are edited in place at close.)
5. **Steward + specialists.** The main session stays small and on-goal.
   Substantive work is delegated to custom `epicflow-*` sub-agent
   personas with bounded budgets and strict output contracts.

## Try it

```bash
# In any repo:
pi
# Then in pi:
/project-init
```

After the 4-question interview, you have a `.pi/project/` brain wired
into `AGENTS.md`. From there, just work normally — pi handles writes
autonomously.

## How v0.13 was built and verified

Two dry-runs gated the release:

1. **Sample notesd CLI** in `/tmp/sample-notesd/` exercised every
   trigger path (defer → BL, decided → DEC, always → C), false-positive
   resistance ("I'll get back to you later" with no work-noun → no
   write), anti-stub PASS on clean code and FAIL on deliberately stubbed
   code, and a live `epicflow-scout` spawn (6/30 read budget, surfaced
   two real footguns and a stewardship meta-flag the steward had
   missed).

2. **Self-dogfood on `pi-epicflow`.** First-run inference extracted 5
   substantive DEC entries, 4 conventions, and 6 BL entries directly
   from the existing README, CHANGELOG, and PLAN files — without a
   single placeholder. The first audit pass found a pre-existing
   PowerShell-parity violation that had escaped 12 prior releases.

Three findings surfaced and were fixed in flight: a placeholder leak in
the conventions template, an in-place vs. append rule for closing
in-progress session entries, and a fence-aware audit awk for example
shapes inside templates.

## Compatibility

- **Pi:** ≥ 0.74 (unchanged from v0.12)
- **Existing repos:** drop-in. Repos without `.pi/project/` see no
  behavior change. Run `/project-init` to opt in.
- **AGENTS.md:** if you already have one, `/project-init` currently
  overwrites — BL-005 tracks the polish to preserve and merge. Back it
  up before running, for now.

## Coming next

Phase 2 of the project-memory pillar is planned but explicitly deferred:

- Standalone `gotchas.md` (currently a section inside `decisions.md`)
- `questions.md` for tracked-but-unresolved items
- Per-module cards under `.pi/modules/<name>.md`
- A dedicated `repo-steward` persona for read-only brain-maintenance
  sessions

These ship when ≥ 5 real users have used Phase 1 for ≥ 2 weeks and
naturally produce content that doesn't fit the existing 6 artifacts.
